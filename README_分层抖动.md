# 分层投影混色抖动（Layered Projection Dither）

把 Krita「按明暗分成 N 层 → 每层套一次色板化滤镜、各调各的参数 → 叠加合成」
那套手工工作流，做成可复现、可批量、可存预设的引擎。

文件：

- `layered_dither.py` —— 引擎（分层投影混色，命令行 / 库都能用）
- `dithers.py` —— 原有的三种基础抖动（有序 / 误差扩散 / 重心混合），未改动
- `GUI.py` —— 界面：分层抖动 + 上述三种基础抖动
- `test/_gui_smoke.py`、`test/_delta_eval.py` —— 冒烟测试与色差评估

## 核心思路：两步分离

```
原始图 ──分层──▶ 每层聚类出少量投影色 ──投影──▶ 投影图（每层只有几种颜色，大片同色）
                                                    │
                                    逐个投影色求"用调色板色把它混出来"的权重
                                                    ▼
                                              抖动图（输出全部落在调色板内）
```

- **第 1 步 投影**：按明暗分层后，每层聚类出 K 个投影色（**允许不在调色板内**），
  层内像素投影到最接近的那个。每层只有 K 种颜色 → 大片区域同色。
- **第 2 步 抖动**：对**每一个投影色单独**求「用调色板色混合出它」的权重
  （凸包内取重心坐标，凸包外先投影到凸包表面），再按图案阈值分配。
  同一个投影色的像素**共用同一组权重** → 输出全部落在调色板内，且该区域的
  抖动图案完全一致，整齐不乱。

为什么这样能同时满足两个互相打架的目标：第 2 步面对的是**单个目标色**，是个单点
问题，不需要所选颜色构成覆盖整个层内分布的凸包（固定调色板做不到那件事）。
**色差不在第 2 步补偿**，而是由第 1 步的投影质量决定 —— 所以想降色差就调
「每层色数」和「层数」。

## 用法

### GUI

`python GUI.py` → 「抖动方法」选「分层抖动」：

- **预设**：标准（投影混色·落盘内）
- **层数**：默认 24。层越细，少量投影色就能覆盖得越准（建议 16 起）
- **每层色数**：默认 8。越大投影越准、色差越低
- **分层依据**：
  - 绝对明度 —— 按明度等分，**保色彩**更好
  - 自适应等频 —— 按图像自身的明暗分布等频分带，**保细节**更好
- **色彩空间**：Lab（推荐，感知均匀）/ RGB
- **保存 / 载入预设…**：Profile 存成 JSON，可复用、可分享

> 桌面版的「编辑分层参数表…」已废弃。逐层、逐颜色的交互调整在**网页版分层编辑器**里做
> （见下一节），桌面版只保留参数面板 + 预设存取。
>
> 图案单元的上限是 **4×4**：8×8 / 16×16 / 32×32 已移除 —— 更大的单元只会让图案跨越
> 感知块，块内平均严重偏离目标色，实测没有额外收益。

## 网页版分层编辑器（三阶段）

浏览器打开 `docs/index.html`（或线上版）→ 方法选「分层投影混色」→ **打开分层编辑器**。

浮窗里三个页签，对应三个阶段，任何一个阶段的改动都会立刻回到成品图：

| 阶段 | 能改什么 | 备注 |
| --- | --- | --- |
| ① 分层 | 拖动**分界把手**自定义每层的阈值；**色阶**黑场/白场/中间调截掉两端的灰 | 拖分界只重分桶，不重跑聚类（40ms 级响应）；改色阶要重新分析 |
| ② 投影 | 每个投影色可换色号或自定义 RGB；**画笔**重划区域；可增删颜色 | 新加的颜色标「待涂」，不涂就不影响画面；删掉的颜色其区域自动并入最近的同层颜色 |
| ③ 抖动 | 每个颜色独立选方法：重心混合 / 有序抖动 / 直接平涂 / 层内扩散 / 二维扩散，各自带参数 | 二维扩散是整图按扫描序做 FS，本颜色取它的结果 |

- **三个阶段的预览**：浮窗顶部三张并排（原色 / 投影色 / 抖动色），都是当前层；
  主画布另有「成品图 / 当前层 × 三个阶段」的切换
- **导出 / 载入工程**：分界、颜色槽、手绘区域、全部参数一起存成 JSON，刷新不丢
- 输出**仍然 100% 落在调色板内**（引擎侧每种方法都验过板外 = 0）

### 命令行

```bash
python layered_dither.py in.png out.png                      # 24 层 x 每层 8 色
python layered_dither.py in.png out.png --bands 32 --colors 12 --scale 0.5
python layered_dither.py in.png out.png --edge-mode quantile  # 保细节
python layered_dither.py in.png out.png --match-space RGB     # 换色彩空间
python layered_dither.py in.png out.png --pattern bluenoise --size 8
python layered_dither.py in.png --analyze --bands 24          # 看各层像素占比
python layered_dither.py in.png out.png --save-profile p.json # 存下这次的参数
python layered_dither.py in.png out.png --profile p.json      # 用存下的参数
```

### Python

```python
from PIL import Image
import layered_dither as ld

pal = ld.load_palette('palette.txt')
img = Image.open('in.png')

prof = ld.make_projection_profile(n_bands=24, colors_per_band=8)
out = ld.render(img, pal, prof)       # 输出 100% 落在 pal 内
out.save('out.png')
```

## 实测（338×600 暗调人像，区域平均 ΔE76，8×8 块平均）

| 配置 | ΔE均值 | ΔE95 | 输出色数 | 板外颜色 |
| --- | --- | --- | --- | --- |
| 24 层 × 8 色，LAB，绝对明度 | 0.954 | 1.81 | 15 | 0 |
| 32 层 × 12 色，LAB，绝对明度 | **0.864** | 1.64 | 15 | 0 |
| 24 层 × 8 色，LAB，自适应等频 | **0.842** | 1.66 | 14 | 0 |
| 24 层 × 8 色，RGB，绝对明度 | 1.384 | 3.03 | 17 | 0 |

- **输出永远落在调色板内**（板外颜色恒为 0，多种素材验证）
- Lab 比 RGB 好一档；自适应等频在暗调图上更优，绝对明度在亮调图上更稳
- 耗时约 2~3 秒（24~32 层）

## 参数怎么调

- **色差偏高** → 提「每层色数」（8 → 12 → 16），或提「层数」
- **颜色发闷、层次不清** → 用「绝对明度」；**细节被吞** → 用「自适应等频」
- **图案阶数不改网点形态，只改灰阶精度**：Bayer 是递归细分的，2×2 与 4×4 画出来的是
  同一族棋盘/对角形态，阶数只决定混合比例能取几档（4 档 vs 16 档）。晚安.jpg @20%
  实测 2×2 与 4×4 只差 13% 的像素、ΔE8 差 0.06，肉眼基本看不出；8×8 与 4×4 只差
  2.1%。要换观感得动**图案类型**（clustered/rounddot 是点簇生长，形态完全不同）
  或 **cell 放大倍数**（cell=2 把颗粒撑到 4px，ΔE8 1.81 → 1.91）
- **想要粗颗粒** → 调 cell、或把图缩小再抖动；**想要细密纹路** → 保持 cell=1 并用 4×4
- **暗面出现方块色团** → 该层图案换掉 `clustered`（它的阈值是环状分布，会被
  凸包混合原样映射成方块色团），用 `bayer` 或 `bluenoise`
- **想收进像素风的粗颗粒** → 先把图缩小再抖动（`--scale 0.4`），之后用最近邻放大

## 2 色模式的量化感知（`mix2_quantize`）

**图案阶数决定了 2 色混合能实现几档比例**：N×N Bayer 只有 N² 个阈值，所以比例只能
取 `step/N²`。2×2 只有 5 档（0/¼/½/¾/1），4×4 有 17 档，8×8 有 65 档。

引擎原先对 t* 做连续求解、再被阈值截断，等于白算：连续最优的 0.62 落到图案上就是
0.5 或 0.75。`mix2_quantize`（默认开）让选色对时直接比"吸附到档位之后的实际落点"。

晚安.jpg @20%（226×178），24 层 × 每层 2 色：

| 取色 | 图案/档位 | ΔE8 | ΔE8_95 | ΔE4 | 纹理 | 色数 |
| --- | --- | --- | --- | --- | --- | --- |
| 连续 t*（旧） | 2×2 / 4 档 | 1.940 | 4.48 | 2.572 | 23.10 | 25 |
| 量化感知 pen0.10 | 2×2 / 4 档 | **1.810** | 4.20 | 2.407 | 19.26 | 27 |
| 量化感知 pen0.07 | 4×4 / 16 档 | **1.657** | 3.93 | 2.358 | 21.55 | 29 |
| 量化感知 pen0.07 | 8×8 / 64 档 | 1.755 | 4.29 | 2.424 | 20.20 | 24 |
| 4 色重心（无 2 色限制） | — | 1.507 | 3.82 | 2.165 | 20.64 | 20 |

- **档位必须跟阶数匹配**：Bayer 是递归细分的，4×4 只给 4 档时输出与 2×2 **逐像素
  相同**（实测 hash 一致）—— 单纯提阶数而不提档位，一点收益都没有。
- penalty 仍然必要：关掉它 ΔE8 反而涨到 2.53（长线段穿近目标、端点却是无关异色）。
- 收益不是普适的：4 张测试图里 3 张改善 2.4%~7.3%，1 张（二次元头像）退化 3.6%。
  `mix2_quantize=False` 可逐个回退。

**能压到的下限由图案档数决定，不由取色算法决定**。2×2 + 2 色在 20% 缩放下，量化
感知已经是这条路线的天花板附近；再降只能动档位（4×4/16 档）或每层色数。

## 观感 vs 色差：端点约束（`docs/dither.js` 的 spanLimit 思路）

2×2 最低非零权重是 25%，所以一个远端异色端点不再是"看不见的杂点"，而是每 2×2 块
一颗的实点。晚安.jpg 实测有 **21.9% 的像素其端点离目标 ΔE > 30**（浅粉区靠
White + Dark Peach 凑色，远端 ΔE 54），画面表现为撒胡椒。

把端点限死确实能清画面，但色差代价很大（同一配置）：

| 端点上限 τ | ΔE8 | 纹理 | 端点ΔE均值 | 远端>30 占比 |
| --- | --- | --- | --- | --- |
| 不限 | 1.810 | 19.26 | 21.5 | 21.9% |
| ΔE ≤ 45 | 1.824 | 19.25 | 21.3 | 21.4% |
| ΔE ≤ 38 | 2.085 | 17.76 | 19.2 | 11.0% |
| ΔE ≤ 32 | 2.274 | 16.12 | 18.2 | 2.4% |
| ΔE ≤ 26 | 2.571 | 17.52 | 17.0 | 0% |

结论：**色差和画面干净在这条路线上是直接对立的**，τ≈45 是"几乎不付代价"的边界，
τ≤38 起每清一分杂点要用 10%+ 的色差换。要不要换看目标媒介。

## 边缘纯色化（`edge_sharpen` / `edge_radius`）

2×2 棋盘的问题不只是色差：**它会把轮廓线打断成散点**。头发丝、翅膀边这些 1~2px 的
线条，一半像素被分到另一色，观感就是"边缘毛、不清晰"。

`edge_sharpen` > 0 时，先把 Lab 三通道梯度的最大值当边缘判据，轮廓像素**不参与混色**，
直接用该区域投影色的主导色平涂。关键在于用「主导色」而不是「最近的板内色」——后者
会跳色（浅粉边缘跳到 Light Peach），实测 ΔE 反而升 15%。

晚安.jpg @20%，24 层 × 2 色，2×2：

| 档位 | edge_sharpen | ΔE8 | 覆盖像素 | 说明 |
| --- | --- | --- | --- | --- |
| 关 | 0 | 1.810 | — | 全部抖动 |
| 强 | 8 | 2.067 (+14%) | 4.3% | 连弱边缘一起收，色差代价明显 |
| 中 | 12 | 1.915 (+5.8%) | 1.9% | **轮廓连续，推荐起点** |
| 弱 | 18 | 1.839 (+1.6%) | 1.5% | 只收最硬的边 |

- **98% 的像素完全不变**，只有轮廓那 1~2% 被改成实色，板外颜色仍恒为 0
- 覆盖越少色差代价越小，但 1.5% 已经能把主线收干净 —— 边缘像素少而关键
- `edge_radius` > 0 会把遮罩膨胀，做出 2~3px 的实色描边，色差代价翻倍（不常用）

## 网页版与桌面版的差异（已对齐）

网页版（`docs/dither.js`）原来有两处与桌面版不同，导致"网页版看着和 Python 版不是一回事"：

| | 桌面版 | 网页版（修复前） | 网页版（现在） |
| --- | --- | --- | --- |
| 2 色取色 | 枚举色对 × 图案档位 | 从四面体 4 色权重里截断 | 同桌面版 |
| ΔE8（同一张图） | 1.81 | 3.80 | 1.91 |
| 切 2×2 / 4×4 的像素变化 | 13.0% | **0.0%** | 11.5% |

**那个 0.0% 是 bug，不是 Bayer 的性质。** 网页版给每层自动导入颜色槽时，
`slotDefaults` 把槽的 `matrix` 写死成 `'bayer4'`，而渲染时「有槽就用槽的矩阵」，
于是面板上的「阈值矩阵 2×2 / 4×4」对成品图完全无效，怎么切都一样。
现在槽默认 `matrixAuto: true`（跟随全局面板），只有在编辑器里手动给某个槽选过矩阵才固定。

## 与 dithers.py 的关系

`dithers.py` 的三个基础方法（有序抖动 / 误差扩散 / 重心混合）保持原样，在 GUI 的
「抖动方法」里照旧可用，未做任何改动。分层投影混色是独立的一条路径，位于
`layered_dither.py`，不依赖 `dithers.py`（但需要 `scipy` 做 Delaunay / 凸包）。

## 已验证

- 落盘：多种素材、多种参数下，输出板外颜色恒为 0
- 色彩空间确实生效：LAB 与 RGB 结果不同（ΔE 0.954 vs 1.384）
- 分层依据两种模式均生效
- 预设往返：`Profile` 存成 JSON 再读回，渲染结果一致；**旧版本多出来的字段会被
  忽略，旧 JSON 仍可载入**
- GUI 全链路离屏跑通：构造 → 生成 Profile → 调参 → 参数表写回 → 出图 → 预设往返
- 旧方法回归：有序抖动 / 误差扩散 / 重心混合三个基础方法均正常
